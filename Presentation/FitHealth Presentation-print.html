FitHealth 01 — The problem
The problem

Health data is fragmented;
decisions are not.

Fitness apps and clinical records live in separate worlds. A doctor sees a patient for a few minutes, twice a year — armed only with what the patient remembers to tell them. Continuous data exists, but never reaches the people who treat it.

FitHealth 02 — Our solution
Our solution

One app. Two roles.
A continuous health record.

For Patients 01
Log everything in one place
Steps, distance, BPM, glucose, blood pressure, water, food and exercise — captured as events, attached to routines.
For Doctors 02
Prescribe combined plans
Assemble medication, diet, exercises and measurable goals into a single routine — and push it to the patient.
For Both 03
Stay connected, in context
An integrated chat carries structured progress reports — not a generic messenger, but a clinical follow-up channel.

FitHealth 04 — Workflow
The core loop

The patient–doctor exchange.

Patient
Logs life as it happens.
  • Logs events: vitals, food, water, exercise
  • Runs personal & prescribed routines
  • Sends progress reports to the doctor
  • Receives updated plans in real time
Continuous data
Vitals, events, reports
Routines, feedback
Clinical context
Doctor
Treats with full visibility.
  • Reviews live patient activity & vitals
  • Composes routines from a clinical library
  • Adjusts plans based on progress reports
  • Maintains multiple patients in one panel

FitHealth 06 — Demo · Routines
Demo · Routines

Medication + diet + exercise, as one plan.

Routines aren't just workouts. They combine measurable goals, prescriptions and daily habits — the unit of treatment that doctors actually want to assign.

  • Prescribed by a doctor, or personal, built by the patient.
  • Tracks medication intake, exercises, dietary targets and goals.
  • Adherence rolls up into the weekly progress report.

FitHealth 07 — Demo · Events
Demo · Events

Every activity, every reading.

Events are the day-to-day log: steps, distance, heart rate, glucose, blood pressure, water, food. Each event can be attached to a routine — building a clean dataset over time.

  • Structured fields — steps, distance, average / peak / min BPM.
  • Routine-aware — events feed back into the assigned plan.
  • Edit & delete — patients keep full control of their record.

FitHealth 09 — Architecture
Technical architecture

One codebase, every surface.

Client · React Native

React Native Expo Router TypeScript
Single codebase ships to Android, iOS and modern browsers. Screens are state-driven, with offline-friendly event capture.

Server · FastAPI

Python 3.12 FastAPI Pydantic v2 JWT auth
REST API with role-based access for patients and doctors. Email verification, password reset and refresh tokens.

Data · PostgreSQL

PostgreSQL SQLAlchemy Alembic
Normalized schema for users, routines, events and chat. Indexed for time-series queries on patient vitals.

Operations · Docker

Docker Compose Nginx GitHub Actions
Reproducible local and production environments. CI runs lint, type-check and tests on every push.
